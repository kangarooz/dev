Onboard one new demo scenario by asking the user questions, then scaffold, inspect, fill in, validate and dry-run it. Optional starting hint from the user (a feature name, or empty): $ARGUMENTS

This command needs the `question` tool and only works in the interactive TUI (`opencode`, then `/onboard`). If the question tool is not in your tool list (that is what `opencode run` does), reply exactly: `onboard needs the TUI: run "opencode" in the kit directory, then type /onboard` and stop.

Rules for this command: one tool call per step. Ask with the question tool only (one `questions` entry per call, `custom` left on so the user can type). Never ask for a password or any secret value, only for the NAMES of environment variables. Never run `creds set` yourself (it is denied; it needs the user's terminal). Use `python`, or the venv interpreter from your instructions, in every command. `<slug>` is the feature name in lowercase with dashes (`Chat with Manuals` -> `chat-with-manuals`).

1. Question, header `Feature`, question `What is the feature called? (used as the scenario name and slug)`, options: the hint above if it is not empty, otherwise `Chat with Manuals`. Remember the answer as `<name>`.
2. Question, header `App URL`, question `Where is the app running? (the scenario opens this URL first)`, options: `http://localhost:3000 (Recommended)`, `http://localhost:8080`, `http://127.0.0.1:8765 (the kit's mock app)`. Remember `<url>` without the text in parentheses.
3. Question, header `Login`, question `How does the app log in?`, options: `none (Recommended) - no login page`, `form - a username/password page`, `basic - HTTP basic auth (browser popup)`. Remember `<login>` = `none`, `form` or `basic`.
4. Only when `<login>` is `form` or `basic`: question, header `Credential names`, question `Which environment variable NAMES hold the username and the password? (names only, never the values)`, options: `DEMO_USER and DEMO_PASS (Recommended)`. Remember `<user_env>` and `<pass_env>`. When `<login>` is `none`, skip to step 5.
5. Question, header `Step 1`, question `Describe step 1 of the happy path as "Title :: what the user does and what should be visible after it"`, options: `Open the app :: open the home page and see the main screen (Recommended)`. Remember it as one `--step` value.
6. Repeat with header `Step 2`, `Step 3`, ... and the question `Describe the next step as "Title :: what happens and what should be visible", or pick Done`, options: `Done - no more steps` first from step 4 on (the user needs 3 to 6 steps). Stop asking after `Done` or after step 6.
7. Run `python -m demo_smoke init-scenario --name "<name>" --url <url> --out scenarios/<slug>.json --login <login> --step "<step 1>" --step "<step 2>" ...` - add `--username-env <user_env> --password-env <pass_env>` when `<login>` is not `none`. Exit 4 (`error:` line): fix exactly the reported argument once and rerun; if `scenarios/<slug>.json` already exists, ask the question `Overwrite scenarios/<slug>.json?` with options `Yes, overwrite`, `No, stop` and add `--force` only on yes.
8. Only when `<login>` is not `none`: print these two lines for the user to run in their own terminal, exactly:
   `python -m demo_smoke creds set <user_env>`
   `python -m demo_smoke creds set <pass_env>`
   Then ask the question, header `Credentials`, `Did you run both creds set commands in your own terminal? (the values go to the kit's .env, which I never read)`, options: `Yes, both are set`, `Skip for now`. On yes run `python -m demo_smoke creds check <user_env> <pass_env>`; on exit 4 (`MISSING`) ask that question once more, then continue and note in the report that login will fail until they are set.
9. Run `python -m demo_smoke inspect <url> --out demo-output/<slug>` - add `--headless` when the user said there is no display; add `--login-from scenarios/<slug>.json` when `<login>` is `form` or `basic` and the credentials are set. It prints one row per input, button, link and file input with a stable selector (first column), its text, placeholder and label. Exit 3 (`error:` line, Chrome or URL problem): report it and stop. Exit 2 (`inspect: FAIL`, login failed): tell the user the login selectors or credentials are wrong and continue without login.
10. Read `scenarios/<slug>.json` with the read tool. For every step, replace `"actions": []` and `"expect": []` using selectors from the inspect table and delete the step's `todo` key. Actions, in order, one object each: `{"goto": "/path"}`, `{"click": "<selector>"}`, `{"fill": {"selector": "<selector>", "text": "..."}}`, `{"upload": {"selector": "input[type=file]", "files": ["fixtures/<file>"]}}`, `{"press": "Enter"}`, `{"wait_for": {"selector": "<selector>", "timeout_s": 10}}`. Expectations, at least one per step: `{"text": "words visible on screen"}`, `{"selector": "<selector>", "contains": "words"}`, `{"selector": "<selector>", "count_min": 1}`, `{"url_contains": "/path"}`. Then write the whole file once with the write tool (valid JSON, no `todo` keys, no other keys added). If a step needs a page you have not inspected, run `python -m demo_smoke inspect <url>/<path> --out demo-output/<slug>` once for it first.
11. Run `python -m demo_smoke validate scenarios/<slug>.json`. Exit 4 (`validate: INVALID`, one `error:` line per problem): fix exactly those problems once with the write tool and validate again; still invalid: stop and report them. `warning:` lines about `todo`, `no actions` or `no expectations` mean step 10 is incomplete: finish it, then validate again (once).
12. Run `python -m demo_smoke dryrun scenarios/<slug>.json --out demo-output/<slug>` (add `--headless` under the same condition as step 9). Exit 2: read `demo-output/<slug>/logs/smoke-results.md`; if a selector was not found, run inspect once on that page, fix the scenario once with the write tool, and run dryrun once more. Exit 3: report the `error:` line and stop.
13. Reply with: the scenario path, one line per step with its dryrun status, the credential names still missing (if any), and the exact next commands:
    `/smoke scenarios/<slug>.json demo-output/<slug>` (add `voices/<name>.wav` at the end when `/clone-voice` produced a voice)
    `opencode run --agent demo-smoke --auto --command smoke "scenarios/<slug>.json demo-output/<slug>"` for the unattended version.
